# Pro 2 desktop 3D

The production Pro 2 route supports desktop depth through its own SBS scope: **3840×1080 at 60 Hz**. Hold **L1** to switch the glasses between 2D and 3D. The [vendor guide](https://www.viture.com/academy/xr-glasses/pro-2) identifies L1 and full SBS at 3840×1080.

## Observed hardware

On November 8, 2026, with XR stopped, the user held L1. Hyprland reported:

| | Before | After |
|---|---|---|
| Output | DP-2 | DP-2 |
| Active mode | 1920×1080 at 120 Hz | 3840×1080 at 60 Hz |
| Scale | 2 | 2 |
| Advertised modes | 1080p at 60/90/120 Hz and fractional variants | Only 3840×1080 at 60 Hz |
| USB | `35ca:1301`, `VITURE PRO 2 XR Glasses`, Bus 001 Device 030 | Same identity and device number |

This establishes the physical button transition and host mode readback.

The installed production bundle `6b43dcb3d52c` then ran desktop depth on XR-1. Run `44cebef2ac87eafcbc90303e364f9f13` reported `phase=on`, `stereo=true`, `failed=false`, healthy tracking, and 59.998 Hz presentation. Read-only inspection of depth metadata showed a 420×266 output map at source sequence 3695, 15.29 ms old, with a 1.32 ms engine heartbeat age. No desktop pixels were saved.

An earlier startup ended when the tracking provider became unready; its windows recovered. A subsequent standalone bridge check ran 19.072 seconds with 2168 samples and no error, and the next production run stayed healthy with depth active. The first tracking interruption's cause is unconfirmed. The wearer then confirmed that depth works and holding L1 returns to 2D. They also reported edge artifacts at higher strength on both desktop borders/text and object outlines; that quality issue is separate from enabling SBS.

The subsequent [high-strength edge refinement](3d-edges.md) documents the rendering changes, before/after evidence, performance, and remaining limitations.

## Installation and use

The depth runtime and an installed Pro 2 bundle containing its launcher are both required. From the checkout, after building the renderer and ownership plugin:

```sh
tools/depth_engine/setup.sh
python -m tools.xr_controller install --build build/release
systemctl --user restart viture-workspace-controller.service
```

The setup script installs the runtime and model under `~/.cache/viture-depth`; it needs network access and substantial disk space. Installation adds `xr-depth-engine` beside the bundle's renderer and includes its hash in the bundle manifest. Existing bundles remain available for rollback.

Start a new Pro 2 session after installation. Its confirmation includes the Pro 2 3D scope. Enable a desktop's 3D control, then hold L1 when prompted. Glasses already in the supported SBS mode need no further button press. No USB mode command is sent; the adapter follows the mode the glasses advertise and verifies any compositor mode request by readback.

Turning desktop depth off makes the rendering flat. Hold L1 to return the physical display to 2D. Holding L1 directly during active depth also stops depth and marks the display transition as expected. The adapter restores the previously observed 1080p refresh if the returned display still advertises it. A session started while already wide preserves the returned narrow mode when no earlier narrow refresh is known.

Only the observed 60 Hz SBS timing is enabled. Pro 2 never uses Luma's 1200p mode or R1 instructions. Production consent keeps `mode_switch=False` and carries the separately validated Pro 2 `sbs_mode`; bounded supervised tests retain their existing no-SBS scope.

Display handovers may restart the renderer while the same USB device and healthy tracking bridge remain. The bridge cannot reconnect across USB loss; a changed device or failed tracking health ends the session through normal recovery.
