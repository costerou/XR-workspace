XR Workspace · pre-start panel redesign

Mockups of the Omarchy panel plugin (omarchy-plugin/cody.viture-workspace/) before a session runs. The running-session page and the in-glasses menus are not part of this. Each page shows its key states side by side at real size: a 520 × 660 floating window in the Omarchy shell's own font, control shapes and the current theme's colours.

Flow

bar widget (07) ──click──▶ Home (01) ──Session setup──▶ Setup (03) ──Back──▶ Home │ └ blocked: Home (02) or Recovery (06), Start disabled, one block says why └──Start XR──▶ Confirm (04) ──Start──▶ Starting (05) ──▶ running page (unchanged, not in this set) └─Cancel──▶ Home └─Cancel start / failed ──▶ Home Recovery (06): Recover… ──▶ Confirm recovery ──▶ Home
01 · Home: ready to start02 · Home: cannot start yet03 · Session setup04 · Confirm start05 · Starting, stopping, failed06 · Recovery07 · Bar widget

Shared rules

  • One window size for every page (520 × 660), so the window never resizes between states. Header is always 44 px: mark + name on Home, Back + page name on sub-pages, close at the right (Esc).
  • Start XR never moves. When it cannot be used it is disabled and exactly one block under it says why and what to do.
  • Three status colours only: neutral (information, history), warning #e7c78a (you need to do something), error #e06c75 (something failed). Today almost everything is amber.
  • All colours are the seven tokens at the top of each file's CSS (Commons.Color background, foreground, accent, muted; the plugin's warning and error; Style.cornerRadius). Controls follow qs.Ui: hairline border, 4% fill, 28 px high, square on this theme.

Decisions

  • Look: build with the Omarchy shell kit (qs.Ui controls, Style.font), not plain Qt controls, so the panel matches the rest of the shell and follows the theme.
  • Window: 520 × 660, fixed.
  • Start steps: wanted. Needs the controller to add the start phase to its snapshot. Until then the Starting page ships with the heading, the indeterminate bar and Cancel, without the list.
  • Start is disabled whenever a start would be refused (no output, more than one pair, Pro 2 without its bridge). The controller keeps refusing as well.
  • Confirm keeps its two switches. Session setup holds the saved default; Confirm can only reduce it for this one run.
  • Copy buttons on the recovery pages are kept.
  • Bar: ready is full foreground, and the right-click menu gains “Open XR Workspace”. Running stays accent, as now.
  • Wording for “multiple VITURE devices” and “presentation connector is not unambiguous” is rewritten in the panel only; the controller strings stay as they are.
