Glass hover states

Overview controls and panel buttons at 1.4× their canvas size, over a see-through scene with two desktops. Each section shows rest, hover and pressed, then a live copy to try with the mouse. Colours are the M3 glass scheme for a blue Omarchy accent, capped at 191/255 like the renderer.

Today: the placement pill and the gear get an 8% state layer in their on-colour (16% while dragged) and a bigger black drop shadow. The Maximize button snaps from primary container to bright primary, its icon flips colour, and a “Maximize” label pops up. Options rows on hover or focus get a secondary-container band, a 2 px primary outline and a bold label. Placement-panel buttons don’t react at all. Every change is a hard step with no fade.

CurrentWhat the renderer draws today

Three different hover styles. The pill and gear barely change: the 8% layer is dark ink, so they dim, and the black shadow is invisible on OLED. Maximize flashes bright. Rows get a thin outline and their text jumps to bold.

ABrighten

One rule everywhere: hover mixes the fill 24% toward primary-bright, press 36%. Every control lightens, nothing dims. No outline, no bold swap, no shadow. 120 ms fade. Maximize follows the same rule instead of swapping to primary.

Maps to: glass_look state colour = primary_bright (not the on-colour); glass_state_opacity 0 / .24 / .36; shadow left at elevation 1 for all states. Maximize hot atlas cell = md_layer(primary_container, primary_bright, .24). Rows and panel buttons: md_fill_rounded with md_layer, outline stroke removed. Ease hover_level instead of stepping it (wayland.cpp).

BGlass rim + sheen

Hover lights the glass from above: a 2 px light rim inside the edge and a soft sheen on the top half. Press drops the sheen and darkens the fill a little, so the control looks pushed in. Looks the most like visionOS, but the rim is the finest detail of the four.

Maps to: outline = primary_bright, outline_alpha by state 0 / .55 / .7 (the open panel already uses this slot). The rim needs a width uniform instead of the hard-coded 1 px. Sheen = state layer with state_px = half the height, plus a soft ramp instead of the ½ px edge (one shader line). Atlas buttons get the same rim drawn with md_stroke_rounded, 2 px.

CLift Recommended

Hover grows the control about 7% (pill +11 px wide, +2 px tall on the canvas) and brightens it 18%. Press shrinks it below rest and brightens it 28%. You can tell a hover from size alone, even out of the corner of your eye. Every control uses the same motion.

Maps to: brighten = A’s state-layer change (opacity .18 / .28). Grow = inflate the rect passed to shape() / image() in gl.cpp by by_state(level, 0, +5.5 / +1, −2.5 / −0.5 px). Radius stays h/2. Hit boxes keep the rest rect, so nothing jitters at the edge. Needs hover_level eased over ~150 ms (like CardFade) instead of stepped. Panel rows and buttons: scale the band rect the same way in render_*_panel.

DInk + affordance

The fill barely changes (10%). Instead, the content shows what will happen. A grip bar appears in the pill and stretches when pressed. The gear and Maximize icons sharpen and grow. A menu row gets an M3 accent bar on its left. Button labels turn primary-bright.

Maps to: the pill grip reuses grabber_look (already drawn for the open panel), placed inside the pill and fading by level. Icons: hot atlas cells drawn at 1.14× with full-strength ink. Row indicator: one md_fill_rounded 4 px bar in primary. State layer .10 / .16 toward primary_bright.

Mockup only. Sizes are canvas px × 1.4. Options rows are shortened to 196 canvas px (568 in the renderer) so four fit side by side. The live column uses real CSS :hover / :active.
