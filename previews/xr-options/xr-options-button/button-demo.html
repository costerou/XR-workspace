Configure / Command · scope contract

Selected monitor: placement (left/right, down/up, distance), size, resolution, scale, curvature, roll/level, maximize, per-monitor 3D enable and strength, ultrawide, remove. Workspace / All monitors: Display stabilization, pose prediction, recenter, overview/next/previous, spacing, follow/locked when maximized, automatic per-glasses remembered setup / confirmed reset, add monitor, global 3D enable, preset, strength and convergence, backgrounds and brightness, input / typing mode, keybind editor and help, send-window commands, physical-display privacy, video open / URL, playback and quality controls. Window memory remains automatic. Profiles here mean automatic per-glasses remembered setup, not a named-profile library. Future native controls apply live through existing owners; forwarding is not applied readback. Removing a monitor evacuates windows to the physical fallback; resetting layout has different migration semantics. Remove/reset require their existing confirmations. 3D switching may require physical R1 and can fail or wait; these inert split segments do not imply instant SBS or engine availability. Video quality includes texture filter and deband; file browsing needs a future XR-safe picker. These are shell destinations, not working settings.

Proposed menus stay on the selected monitor’s surface at the press-time pose while open, with enough downward view allowance; no head-locked target chasing. Only one shell per session. Browser Escape restores focus to its trigger; outside click dismisses only in this mockup. Native desktop press currently passes through to the app and releases menu keys while leaving placement visible; the production handoff must be designed explicitly. Browser Tab is not the native placement Tab command (which changes monitor). Existing pill click/drag remains reserved.

Safety recommendation: retain minimal external measured session/status and emergency Stop when XR picture or tracking fails. Show Recover only in recovery-needed state, preserving its confirmation/disclosure flow. Keep it reachable on the physical fallback display; if that display disappears, report blocked recovery rather than promise evacuation. All other post-start controls belong inside XR; startup configuration stays before Start.

Geometry: source pill width clamp(.24 × tile width, 64, 160), height 14, gap 10. Here 480 / 560 px monitor surfaces yield 115.2 / 134.4 px pills. Options targets are 38–40 px tall, ≥40 px wide, with ≥2 px clearance from the reserved pill target (including its 10 px source padding); no overlapping invisible padding. B4 keeps the pill hit area separate despite its visual bridge. Existing top 3D stays 40 + 2 + 28 px, scaled with level bar (120/148 here). Both top and lower handles in maximized view are illustrative proposed additions: source currently exposes overview handles only. Overview neighbors are clipped silhouettes, not native monitor captures. Native geometry is still unproven: distance compensation, curved/rolled projection, occlusion, narrow tiles and half-open hit ownership need contract tests.
