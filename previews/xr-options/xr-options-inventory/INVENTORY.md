# XR options inventory — complete source audit — complete source audit

Shared planning contract: no production changes. Preserve every runtime control.

- **Selected monitor · XR-n**: placement (orbit, distance, curvature, roll/level), resolution, scale, ultrawide, monitor 3D/strength, maximize, remove. Keep existing drag pill and Connected Tail 3D; new Options below monitor beside pill, with separate hit zones.
- **Workspace / All monitors**: Display stabilization, spacing, prediction, global 3D/look/screen plane, backgrounds/brightness, add monitor, reset remembered layout.
- **View & Input**: overview/maximize, follow/locked (maximized only), recenter, select previous/next, typing/control mode, keybind editor, send windows, privacy.
- **Video**: file/browser link, playback/seek/format, controls visibility policy, texture filter/deband, return to desktops.
- **Help & Session**: paged help, measured status, Stop. Explicit recommendation: retain external status + emergency Stop/Recover when XR picture/tracking fails.
- **Before Start only**: fallback output, tracking enable/driver and consented physical mode switch. Startup resolution/scale editor is startup-only as a route, but resolution/scale themselves DO change live through native pills.

Profiles are automatic remembered per-glasses setup, not an invented runtime profile picker. Quality menu/keybind/privacy/send-window actions must not disappear merely because desktop QML does not advertise them.

## Migration path and native contracts

1. Preserve the supervisor as mutation authority. Native renderer draws menu state and reports hit geometry; it must not run shell commands or maintain a second settings truth. Route Options intents through ViewControl and existing desktop, immersive, video, environment and keybind workers. Keep slow broker/driver/network work off the watchdog loop. First move existing runtime surfaces without deleting controls; simplify RunningEditor only after parity is proven and Cody selects a visual design.
2. Add a distinct options affordance below each monitor beside its drag pill. Keep Connected Tail 3D and roll bar. Update both glass.hpp/glass.cpp mesh/hit geometry and free_pointer.py together; padded hit areas must not overlap pill drag, monitor border resize, app content, or 3D tail. Preserve release cancellation, front-to-back hit order, curved/rolled surface projection and captured press-time surface while sliders move.
3. Separate Selected monitor · XR-n from Workspace / All monitors visibly. Background and brightness currently occur inside each placement panel but are global. Selection indices are not stable monitor identities: removed names leave gaps. Global 3D enable clears exceptions; per-monitor toggles/strengths use XR-n names. Preset changes convergence; strength UI percent is half the integer wire value. Keep requested, switching, applied and failed states distinct; SBS requires consent and physical R1, with 2D fallback.
4. Renderer IPC currently has typed view, placement, placement_menu, roll, desktops, environment, immersive, help, binds and video payloads. Options needs explicit open/close, section, selected stable monitor, focus/row, picker state, disabled/busy/reason and hover/pressed fields or a versioned dedicated payload. Do not overload placement_menu field ordering: brightness is already its fifth logical field while WirePlacement has four values. Roll is a separate hundredths-degree value, not a fifth placement member. Check bounded row/text counts, printable ASCII fallback, numeric ranges and stale session rejection on both ends. New operations require decode_control allowlist, xr_control helper, controller allowlist/capabilities and tests only where intentionally externally exposed.
5. Controller schema:1 request_id frames (16 KiB) and run_id/session private control frames are different layers. Forwarded means sent, not applied. Status must report active selected/name/count, busy/armed/pickers, view mode/zoom, live setup and all saved runtime settings needed by native controls. Existing controller view_op allows USER_OPS and VIDEO_KEY_OPS only: menu, quality navigation, typing, privacy, binds and send actions cannot simply be called through it today. Native paths already own these. video_quality accepted by set_settings has no live forward branch; retain native Q quality path or explicitly implement/verify an absolute setter later.
6. Simplified external running shell: session identity/model/output, uptime, actual mode, health/incident summary, Stop; Recover in recovery-needed and existing CLI recovery guidance when required. **Explicit safety recommendation: retain an external emergency Stop/Recover escape hatch independently reachable when XR picture/tracking/input fails.** Keep confirmation scope and recovery journal; never replace recovery with restart-controller or restart-plugin. Idle shell retains startup scope configuration and consent. Startup-only fallback/tracking/driver/physical refresh policy require a new session; virtual monitor resolution/scale/count do not inherently require restart.
7. Keep automatic per-glasses profiles and window memory. There is no current named-layout picker or backup Restore command. Do not invent either as an existing feature. Saved mode anchor is schema compatibility, not a restored viewing choice. Removed cursor-follow, cursor-switch animation, facing yaw/pitch and legacy menu-mouse operations are not current runtime options; xr_control keeps legacy names only for stale-bind cleanup. Physical output refresh/render scale/codec/bitrate are not runtime quality controls.

## Migration path and native contracts

1. Preserve the supervisor as mutation authority. Native renderer draws menu state and reports hit geometry; it must not run shell commands or maintain a second settings truth. Route Options intents through ViewControl and existing desktop, immersive, video, environment and keybind workers. Keep slow broker/driver/network work off the watchdog loop. First move existing runtime surfaces without deleting controls; simplify RunningEditor only after parity is proven and Cody selects a visual design.
2. Add a distinct options affordance below each monitor beside its drag pill. Keep Connected Tail 3D and roll bar. Update both glass.hpp/glass.cpp mesh/hit geometry and free_pointer.py together; padded hit areas must not overlap pill drag, monitor border resize, app content, or 3D tail. Preserve release cancellation, front-to-back hit order, curved/rolled surface projection and captured press-time surface while sliders move.
3. Separate Selected monitor · XR-n from Workspace / All monitors visibly. Background and brightness currently occur inside each placement panel but are global. Selection indices are not stable monitor identities: removed names leave gaps. Global 3D enable clears exceptions; per-monitor toggles/strengths use XR-n names. Preset changes convergence; strength UI percent is half the integer wire value. Keep requested, switching, applied and failed states distinct; SBS requires consent and physical R1, with 2D fallback.
4. Renderer IPC currently has typed view, placement, placement_menu, roll, desktops, environment, immersive, help, binds and video payloads. Options needs explicit open/close, section, selected stable monitor, focus/row, picker state, disabled/busy/reason and hover/pressed fields or a versioned dedicated payload. Do not overload placement_menu field ordering: brightness is already its fifth logical field while WirePlacement has four values. Roll is a separate hundredths-degree value, not a fifth placement member. Check bounded row/text counts, printable ASCII fallback, numeric ranges and stale session rejection on both ends. New operations require decode_control allowlist, xr_control helper, controller allowlist/capabilities and tests only where intentionally externally exposed.
5. Controller schema:1 request_id frames (16 KiB) and run_id/session private control frames are different layers. Forwarded means sent, not applied. Status must report active selected/name/count, busy/armed/pickers, view mode/zoom, live setup and all saved runtime settings needed by native controls. Existing controller view_op allows USER_OPS and VIDEO_KEY_OPS only: menu, quality navigation, typing, privacy, binds and send actions cannot simply be called through it today. Native paths already own these. video_quality accepted by set_settings has no live forward branch; retain native Q quality path or explicitly implement/verify an absolute setter later.
6. Simplified external running shell: session identity/model/output, uptime, actual mode, health/incident summary, Stop; Recover in recovery-needed and existing CLI recovery guidance when required. **Explicit safety recommendation: retain an external emergency Stop/Recover escape hatch independently reachable when XR picture/tracking/input fails.** Keep confirmation scope and recovery journal; never replace recovery with restart-controller or restart-plugin. Idle shell retains startup scope configuration and consent. Startup-only fallback/tracking/driver/physical refresh policy require a new session; virtual monitor resolution/scale/count do not inherently require restart.
7. Keep automatic per-glasses profiles and window memory. There is no current named-layout picker or backup Restore command. Do not invent either as an existing feature. Saved mode anchor is schema compatibility, not a restored viewing choice. Removed cursor-follow, cursor-switch animation, facing yaw/pitch and legacy menu-mouse operations are not current runtime options; xr_control keeps legacy names only for stale-bind cleanup. Physical output refresh/render scale/codec/bitrate are not runtime quality controls.
