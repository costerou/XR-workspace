# XR settings migration: independent feasibility and completeness audit

Review base: `origin/master ff7b26a`. Planning only; no production changes, installation, device access, or compositor mutations. Source inspection, not a live XR validation. HTML reconstructions are mockups, not native renderer screenshots.

## Recommendation

Proceed to design selection with a compact, monitor-adjacent Options entry opening a bounded native-style Configure/Command panel. Use explicit **Selected monitor · XR-n** and **Workspace / All monitors** scopes. Preserve the existing placement/drag pill and Connected Tail 3D control. Reuse the existing supervisor, desktop manager, renderer, and persistence owners; do not introduce a second configuration authority in a web view. A faithful interactive HTML prototype is sufficient for visual selection; native mockups are not a prerequisite. Native geometry/input contract tests are required during implementation.

**Explicit safety recommendation:** retain a minimal external session/status surface with emergency **Stop**, and **Recover** when recovery is needed. This is a deliberate exception to moving runtime settings into XR. It must remain reachable on the physical fallback display when the XR image, tracking, capture, or renderer fails. Do not bury it behind an XR menu, or replace recovery with an unguarded output-delete command. Keep pre-start setup and consent externally. Remove duplicated desktop runtime editors only after equivalent XR paths are verified.

The migration is feasible, but not a pure rearrangement of QML. The current native placement payload has a finite, strict decoder and the existing free pointer operates in overview. Scrolling, generalized keyboard focus, an Options hit region, and any menu that remains usable while maximized require deliberate native contracts. Do not advertise those as already implemented.

## Specific blocking misses to resolve before production migration

B1. **Lifecycle escape must survive the migration.** External “running” cannot simply disappear. Preserve Stop through controller state gating, recovery-needed status and the existing begin/confirm recovery flow (including removable monitor-rule disclosure). A dead renderer must not be needed to restore windows. No physical fallback available: pre-start refuses rather than starting an unrecoverable session (`begin_start`, `Launcher.qml`). If the fallback disappears during a run, report the blocked recovery; do not promise guaranteed evacuation.

B2. **General menu focus is absent from today's placement contract.** Current Up/Down selects a placement field; Left/Right edits; Tab changes monitor, not widget. Plain R/U/N/Shift+Delete have commands. A prototype with ordinary browser Tab traversal is not proof these semantics exist natively. Specify a menu-local focus order, visibly focused element, activation, slider stepping and picker navigation; retain/remap existing commands deliberately, showing hints. Preserve app typing after desktop click (`desktop_press` disables menu binds), and reacquire on panel click (`panel_keys_on`). The bind editor captures all keys via a different modal path: close/suspend options ownership before opening it.

B3. **Scroll and Escape must be explicit.** Existing placement pointer code provides no generalized menu wheel-scroll route. A long full panel needs bounded clipping, scroll offset in both render and hit test, keyboard paging, and wheel capture only over the menu. Otherwise use paged groups with explicit buttons. Layer Escape: cancel key capture/dropdown first, close options next; video Escape retains exit-video behavior. Do not let one key dismiss two layers or reach an app. Outside click must define consumption: current desktop press passes to the window and leaves the panel visible; do not silently change it to a swallowed click. Idle close currently occurs at 30 seconds; preserve cleanup and avoid timing out an active drag/capture.

B4. **Anchor and target stability need a contract, not just CSS.** Share `glass_anchor`/distance compensation, projection/unprojection and exact rectangles between renderer and Python. Current panel scales to preserve chrome size as desktop distance changes; curvature and roll transform its surface. Freeze the press-time placement while dragging sliders (`menu_surface`, `pill_slide`), then release. Keep the selected monitor identity stable through an edit; automatic follow-focus can otherwise retarget a different desktop. Freeze target during pointer capture and explicitly dismiss/rebind on output removal. Support current front-order/occlusion logic rather than letting invisible zones steal presses.

B5. **Overview/maximized behavior must be honest.** Lowest-risk first version: Options from maximized view returns to anchored overview, opens the selected monitor menu, and explains the transition. This matches `_zoom_out` and pill behavior. Do not silently auto-maximize on close. A persistent maximal-view menu would require new presentation and pointer paths; treat it as extra scope, not a free variation. Placement edits sent while maximized are currently held until overview. Mockups must show both contexts and that transition.

B6. **No-monitor cases have two meanings.** No normal physical monitor: Start remains unavailable with explanation. No XR desktops is not a supported normal state: decoder rejects empty placements and desktop manager prevents removing the last. A prototype empty state must not imply removal-to-zero is supported. For transient missing capture/output, keep global session recovery/status reachable externally; a monitor-attached menu cannot be the sole emergency route. Do not add dummy outputs to fix a mockup.

B7. **Live preview is already persistence, not a cancelable draft.** Placement applies live, saves after 500ms idle and flushes on close; environment/3D/view have their own saved owners. No global Apply/Cancel affordance unless an actual draft/rollback contract is planned. Label “Changes apply live”; distinguish pending/switching, applied readback and failure. Retain defaults and persistence scopes, including per-run follow/locked and saved per-model setup/roll. Do not show “Saved” solely on controller forwarding. Strength display currently divides internal 0–200 by two in QML: choose one consistent displayed unit and convert exactly once; do not copy raw numbers into a browser slider with a different range.

B8. **SBS cannot be an instant switch.** `ImmersiveRun` starts engine before entering SBS and renderer; off flattens renderer first. `ButtonSbs` can ask for R1, wait up to 45s, detect advertised 3840×1200 modes, use 90/60Hz, and recover from expected output disappearance. Off may still require R1 to restore physical 2D/120Hz. No guessed USB command. Show switching, physical instruction, unsupported/no engine/no consent, failure/fallback and retry; saved desire may remain on while applied rendering is 2D. Desktop 3D stands down during VR video. The external escape must work while XR instructions are invisible during a mode change.

B9. **Preserve all hit zones, not only visible spacing.** Options must be below the monitor beside the placement pill, leaving Connected Tail 3D and level bar intact. Audit expanded invisible pill margins (`on_pill`) as well as drawn rectangles, resize-corner bands and bars (`hit`). Half-open nonoverlapping ownership rectangles, an inert gutter and a press-latched target are needed. Options press must never become pill drag after slight movement; pill drag must never toggle Options. Test narrow/tall/ultrawide tiles, largest/smallest distance, curvature 120°, ±roll, overlapping desktops and menus. Do not shrink all controls to fit one screenshot; put the pair in a wider reserved chrome row if necessary.

B10. **Coverage cannot stop at external buttons.** Include native-only keybind/privacy/window-send/video-quality controls in the navigation map. Keep workspace controls visibly global and selected controls labelled XR-n. No speculative profile picker, per-monitor stabilization or obsolete yaw/pitch. Separate dangerous reset/remove confirmation from ordinary dismissal. Display truthful busy/error/unsupported states and valid scale choices.

## Exact low-risk implementation boundary (future work only)

1. Extend supervisor-owned menu state with explicit scope/page, selected XR-n, focus key, open picker and scroll/page offset. Keep renderer state a bounded presentation snapshot; menu events become validated intents addressed to run/session and monitor identity. Reuse existing replay protection and validation style. Do not stuff arbitrary nested JSON into the strict placement-menu payload; add a separately bounded options payload/control contract with dedicated malformed-frame handling, preserving old placement frames during transition.
2. Add a geometry definition for the adjacent Options region and panel parts. Mirror it in Python with contract tests as the existing glass geometry does. Draw native themed chrome in the presentation pass after managed output captures; no new virtual monitor, browser process, capture stream, input plugin or compositor cursor hook is necessary for settings chrome.
3. Route intents inside `ViewControl` to existing validated setters/workers: placement + bump/save; desktop manager + guard pause/readback/resume; environment; immersive worker; stabilization; view ops; existing bind/video panels. Refactor shared validation if needed rather than calling the external QML or making it a second broker. Reuse ownership broker transactions for resolution/add/remove and evacuation; never manipulate output rules directly from a button.
4. Give menu ownership a single lifecycle: open, pointer/key interaction, suspend to child editor/video or app typing, resume, close, renderer restart, run stop/error. Release pointer and modal binds on every terminal path. Keep controls/status synced from applied supervisor state; reacquire bounded menu snapshot after renderer restart without reissuing destructive commands.
5. Migrate desktop runtime editors last. External running surface becomes model/output/session state, Stop, actionable failure/Recover, plus startup-only choices disabled or clearly marked “Next start”; changing consented startup scope requires stop/start and fresh consent, not a live toggle. Do not add a one-click restart that hides evacuation or confirmation.

## Verification gates for the eventual build

- Geometry parity and round-trip projection at moved/resized/curved/rolled placements; no overlap between Options, pill, corners, Connected Tail or expanded hit margins. Include panel clipping and active scroll hit offset.
- Pointer press/move/release, desktop focus/typing handoff, all menu keyboard paths, nested Escape, modal teardown after crash/restart/stop and bind-editor timeout. No command leaks into the focused application.
- Live readback + persistence for each control, reload/start restoration, unsupported values, remove-last and add-limit, failed resize/scale/output evacuation, stale XR-n after remove/add, double-confirm reset/remove.
- Stabilization 0/25/100 without changing prediction semantics; 3D desired versus applied, no-engine/no-scope/failure/retry, expected SBS output drop, video handoff and physical R1 return instruction.
- Stop/Recover with failed XR picture/tracking/capture and unusable fallback. These later integration checks need a controlled implementation phase; no live XR was touched for this audit.
- Visual selection: readable XR-scale overview and maximized transition, normal/hover/open states, actual pointer and keyboard dismissal, full content reachable without clipping. Browser HTML/PNG/MP4 demonstrate design only; no native screenshot claim.

### Selection advice

Prefer **B3 labelled Options + C2 grouped drill-in**, with explicit scope header and a short fixed group list; C1 is a reasonable alternative for fewer navigation steps. Use full F1 as a coverage/reference inspector, not the default spatial footprint. Avoid detached F2 and a maximal-view attached menu for the first migration: both cost new coordinate/input work. Keep placement pill behavior and native child editors available throughout. Correct the listed prototype fidelity issues before asking Cody to approve the detailed interaction contract; do not require a native mockup to choose the visual direction.

No production feature code changed. This audit owns documentation, independent browser evidence and its check script only; sibling design workers own HTML/contact-sheet/animation deliverables.
